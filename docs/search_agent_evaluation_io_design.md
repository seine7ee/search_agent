# Search Agent 质量评估：具体输入输出设计

版本：v1.0

对应主方案：[通用问答助手的 Search Agent 轨迹质量评估方案](/Users/seinelee/Documents/my_search_agent/docs/search_agent_trajectory_quality_evaluation.md)

本文将主方案细化为字段契约、输入组织方式、输出报告和完整示例。只给出文档，不包含程序代码或 JSON Schema。评分权重、硬门槛沿用主方案；示例全部虚构，不代表对真实轨迹的评估。

## 1. 接口总览

从业务上保留三类评估，从信息隔离上将 Turn 评估分成决策、收益、停止三个子任务。

| 评估单元 | 粒度 | 最小输入 | 主要输出 |
|---|---|---|---|
| 封闭问题结果评估 CLOSED_RESULT | 一条 query 的最终交付 | 原问题、必要上下文、实际交付网页、时间与范围 | 网页可导出的候选答案、证据链、消歧判断、C1—C4、缺口、回答准备度 |
| 开放问题结果评估 OPEN_RESULT | 一条 query 的最终交付 | 原问题、必要上下文、实际交付网页、时间与范围 | 必要回答义务、可支持的回答提纲、证据与覆盖矩阵、O1—O4、缺口 |
| Turn 决策评估 TURN_DECISION | 一次搜索决策 | 当轮实际 messages、当轮动作、当时有效约束 | T1—T4、逐 action/query 问题、决策可接受性 |
| Turn 收益评估 TURN_OUTCOME | 一次动作批次执行 | 截至动作前的采集记录、本轮动作、本轮返回 | 新事实、可信度提升、消歧等收益，剩余缺口与工具错误 |
| STOP 评估 TURN_STOP | 一次模型 STOP | STOP 前实际 messages、STOP 原始输出、当时有效约束 | 停止类型、0—4 分、未闭环目标、是否可作成功停止示范 |

CLOSED_RESULT 与 OPEN_RESULT 不依赖 Turn 评分。Turn 决策评分也不依赖最终结果 Judge 的结论。它们的结果只在最后的汇总层相遇。

“两个核心 Judge”指结果 Judge 和 Turn Judge 两种职责，不代表每条轨迹只需调用两次模型。逐轮前缀评估和长网页分批审阅的调用次数随输入规模变化。

## 2. 公共输入契约

### 2.1 区分审计元信息与模型可见输入

以下信息由评估编排层维护，不要求 Judge 自行生成，也不必全部占用模型上下文。

| 字段 | 必填性 | 含义 |
|---|---|---|
| evaluation_id | 必填 | 本次评估唯一标识 |
| trajectory_id | 必填 | 被评估轨迹的唯一标识 |
| evaluation_type | 必填 | 本次评估单元类型，与第 1 节一致 |
| target_turn | Turn 类必填 | 被评估的真实决策编号；结果评估不适用 |
| input_snapshot_id | 必填 | 不可变的输入快照版本 |
| policy_version | 必填 | 评分标准、权重、门槛与风险政策版本 |
| judge_revision | 运行时填写 | Judge 模型与提示词版本 |
| execution_status | 运行时填写 | 成功、模型调用失败、输出无效、待重试等评估执行状态 |

教师系统名称、模型品牌、已有总分、人工“优质样本”标签默认不传给 Judge，以减少身份与结论诱导。轨迹身份、版本和调用统计保留在审计记录中。

### 2.2 用户任务 Task

| 字段 | 必填性 | 内容与边界 |
|---|---|---|
| user_query | 必填 | 用户原始问题，不能只提供教师改写后的 search_goal |
| relevant_conversation | 条件必填 | 解释指代、用户偏好或范围所必需的历史对话；独立问题可为空 |
| query_time | 条件必填 | “目前、最新、近三年”等问题的解释基准；未知时明确标记 |
| temporal_scope | 条件必填 | 明确给定的事件范围与信息公开时间边界，不自行将两者混同 |
| scope_constraints | 有则填 | 地区、对象、指标口径、回答深度等用户明确约束 |
| task_type_hint | 可选 | CLOSED、OPEN、MIXED 或未分类；Judge 需要检查，而不是盲从 |
| requirement_seed | 可选 | 仅从 query/用户说明得到的轻量需求骨架，包含来源和版本 |

没有 requirement_seed 时，结果 Judge 在输出中生成必要回答义务。普通 query 不需要额外部署 Query Decomposer。跨系统对比与金标评估应先固定同一需求骨架，避免按各自网页改变覆盖分母。

### 2.3 实际交付网页 Handoff

| 字段 | 必填性 | 内容与边界 |
|---|---|---|
| handoff_snapshot_id | 必填 | 下游实际输入的版本；可来自真实日志的不可变快照 |
| delivery_mode | 必填 | 正文、摘要、混合片段或仅 URL |
| actual_handoff_text | 必填 | 下游实际收到的文本及顺序；不替换成抓取池中的更完整正文 |
| delivered_pages | 必填，可为空集合 | 交付网页及其定位索引；空集合代表实际没有交付网页，不代表日志丢失 |
| handoff_notes | 有则填 | 实际传给下游的摘要、来源说明、限制和冲突提示；没有则为空 |
| completeness_status | 必填 | 已完整恢复、已可靠重建、仅部分恢复或无法确认 |
| truncation_notes | 有则填 | 已知正文裁剪、长度截断和遗漏范围 |

actual_handoff_text 是下游可见内容的事实来源，delivered_pages 是其索引，不应在提示词中重复粘贴同一段正文。若只能恢复结构化网页列表，应明确下游顺序或拼装是否已确认。

只有 URL 而没有下游随后获取的正文时，不能声称完成了“正文是否支撑答案”的评估。应输出可评范围与所缺快照。

### 2.4 网页对象 Page

| 字段 | 必填性 | 含义 |
|---|---|---|
| page_id | 必填 | 评估包内唯一标识；原 ID 冲突时增加命名空间，保留映射 |
| snapshot_id | 必填 | 本次实际使用的网页文本版本，不只是 URL |
| url | 原记录有则填 | 来源地址；缺失不得伪造 |
| title、source_name | 原记录有则填 | 网页标题与来源声明；不能仅凭来源名称判定可信 |
| published_at、retrieved_at | 原记录有则填 | 发布时间、采集时间；不能互相代填 |
| event_time | 可选 | 仅在原文明确时提取，附原文位置 |
| content_type | 必填 | FULL_TEXT、SNIPPET 或 SUMMARY，说明可见材料形态 |
| content | 必填 | 此视图内真实可见的文本，不补全链接正文 |
| span_index | 必填 | 稳定的段落/片段编号，与文本位置对应，可由评估适配层附加 |
| origin_group_hint | 可选 | 已知原始来源或转载链线索；Judge 应核对，不默认其准确 |
| visibility_note | 有则填 | 截断、表格缺列、只见搜索摘要等限制 |

时间字段缺失不一律使网页无效；只有其影响任务判断时才构成阻塞。正式输入必须包含可读的 content，只有 page_id 或哈希而没有文本不能供 Judge 审阅。

### 2.5 可选参考与审计材料

| 对象 | 字段 | 使用规则 |
|---|---|---|
| reference_answer | 答案、适用范围、来源、版本、可信状态 | 仅封闭子任务使用；不能直接充当 W_final 的证据 |
| external_audit | 审计材料、获取时间、来源与用途 | 只能核验或发现缺口，不能提高原交付的覆盖分 |
| observability_issues | 缺失内容、受影响阶段、是否可恢复 | 解释“不可评估”，不直接证明搜索质量差 |

优先先固定从交付网页提取的候选答案，再进行参考答案对照。若为降低成本在同一次调用中提供参考答案，应标记“联合对照模式”，承认候选提取可能受到答案提示影响，并加强证据定位检查。

### 2.6 缺失值约定

- **空集合：** 完整输入中实际没有这一类记录，例如已确认无冲突。
- **未知/不可评估：** 有关记录缺失或证据不足以判断；不能以空集合或数值 0 代替。
- **N/A：** 该评估项确实不适用，例如外部上限终止没有模型 STOP。
- 数值分只在该项可评时填写；不可评估项不参与完整总分验收。
- 空证据包是可观察的结果不足；丢失证据包则是观测不足。两者必须产生不同状态。

## 3. 公共输出契约

### 3.1 输出总览

| 输出块 | 必填性 | 内容 |
|---|---|---|
| assessment_status | 必填 | COMPLETE、PARTIAL 或 UNASSESSABLE，表示本次评估完成程度，不表示任务完成程度 |
| task_interpretation | 必填 | Judge 理解的问题类型、实体、时间、范围及尚未解决的歧义 |
| reroute_request | 条件必填 | 输入类型与实际任务不符时，说明建议改为 CLOSED、OPEN 或拆成 MIXED 子任务的依据；不能强套当前量表 |
| scorecard | 可评时必填 | 逐维度分、适用性、依据与扣分原因 |
| findings | 必填，可为空集合 | 已确认问题与疑似问题，分别标记 |
| review_requests | 必填，可为空集合 | 需要复核的具体问题、影响与最小新增材料 |
| stage_conclusion | 必填 | 当前阶段的准备度或决策结论；不直接替代整条轨迹的 PASS |
| calculation_details | 汇总时填写 | 权重、折算分、分子分母、总分、门槛结果 |

COMPLETE 表示“评估已完成”，完全可能对应 INSUFFICIENT 的搜索结果。evaluation 的执行失败另由编排层记录，不伪装成 Judge 的质量结论。

### 3.2 每个维度 ScoreItem

| 字段 | 含义 |
|---|---|
| dimension_id | C1—C4、O1—O4、T1—T4 或 STOP |
| applicability | APPLICABLE、NOT_APPLICABLE 或 UNASSESSABLE |
| score | 可评时取 0—4 整数；否则留空并说明原因 |
| rationale | 针对本维度的简短可审计说明，不要求隐藏推理过程 |
| supporting_refs | 加分依据；网页或动作定位 |
| issue_refs | 扣分所对应的问题编号 |
| uncertainty | 未核验范围及其是否影响结论 |

权重和折算分按政策由汇总层填入并复算，不让 Judge 为当前样本临时改变权重。维度分表不是独立的百分比正确率。

### 3.3 证据引用 EvidenceRef

网页引用必须带：page_id、snapshot_id、span_id、原文摘录以及该片段支持或反驳什么。动作引用必须带：turn_id、action_id/query_id 或原始响应片段位置。

缺失项不能伪造一个网页引用。缺口依据可写“在完整审查的 W1—W8 中，没有支持 R3 的片段”；必须同时记录已审范围，不能声称证明互联网中不存在该信息。

### 3.4 问题与缺口 Finding

| 字段 | 含义 |
|---|---|
| finding_id | 稳定问题编号 |
| category | 内容、证据、冲突、边界、过程或观测问题 |
| severity | 轻微、重大或关键失败 |
| certainty | CONFIRMED 或 SUSPECTED；怀疑不当作已确认失败 |
| description | 具体问题，不只写“信息不足” |
| related_requirements | 影响的回答义务编号；不适用时说明 |
| evidence_refs / searched_scope | 正反证据位置，或缺失判断对应的已审材料范围 |
| answer_impact | 下游因此不能确定什么、可能误说什么 |
| visible_to_answer | 缺口或限制是否能从原交付识别：YES、NO、UNKNOWN；纯过程问题可为 N/A |
| suggested_resolution | 最小核验、补搜、澄清或修复方向 |

该输出是审计结果，不自动成为原始交付包的一部分。

## 4. 封闭问题评估：具体输入与输出

### 4.1 输入内容

必填：Task、Handoff、观测完整性说明、评分政策。可选：参考答案、独立审计材料、预先固定的轻量需求骨架。

默认不传：完整搜索轨迹、教师模型身份、历史总分、没有交付的网页、没有交付的 STOP 理由、下游已经生成的答案。

这使封闭结果 Judge 专注于“这些材料能否支持作答”，不因教师写了一段自信的闭环理由而高估准备度。

### 4.2 特有输出

| 输出字段 | 具体内容 |
|---|---|
| answer_obligations | 最小必要条件及验收标准；由 query 与网页绑定未知实体后确定，不能因缺证据删除条件 |
| candidate_answer | 从网页可导出的最小答案、适用范围及引用；无法导出时为空并给出缺口 |
| alternative_candidates | 有证据支持的其他候选及能否排除；不得为了凑候选凭空猜测实体 |
| evidence_chain | 从前置条件到候选答案的各关系、支撑片段和缺失节点 |
| uniqueness_check | UNIQUE、MULTIPLE、NOT_ESTABLISHED 或 UNASSESSABLE；对集合型问题还检查边界与遗漏 |
| premise_resolution | NORMAL、CORRECTION_SUPPORTED、UNRESOLVED 或 NOT_CHECKED；不要求每题都独立核验全部前提 |
| reference_check | NOT_PROVIDED、MATCH、MISMATCH、REFERENCE_DISPUTED 或 UNASSESSABLE，附对照理由 |
| readiness_status | READY_DIRECT、READY_CORRECTION、PARTIAL、CONFLICTED、AMBIGUOUS、INSUFFICIENT 或 UNASSESSABLE |
| scorecard | C1 链路完整性、C2 答案确定性、C3 决定性事实可靠性、C4 交付可用性 |
| coverage_metrics | 必要覆盖率与核心事实支持率，含逐项状态、分子、分母和不可评项；参考答案中的事实不能补入交付支持分子 |
| blocker_list | 未达到确定作答门槛的具体阻塞项 |
| external_verification_status | 未核验、已核验支持、已核验反驳或仍无结论；不与 readiness_status 混用 |

若没有发现有证据的第二候选，但必要条件仍未核实，应输出 NOT_ESTABLISHED，不能因为“只找到一个”就输出 UNIQUE。

### 4.3 最小答案的角色

candidate_answer 是答案准备度的检验产物，不是要求 Search Agent 原来输出过答案。它必须能由实际交付材料导出，不能来自 Judge 常识或仅来自参考答案。

封闭结果门槛沿用主方案：C1＝4、C2＝4、C3≥3、C4≥3，无关键阻塞。阶段通过不代表整轨迹 PASS。

### 4.4 完整示例：唯一答案已有证据

以下机构、产品、日期、页面均为虚构。示例字段仅用于展示接口，不是实际联网结果。

#### 输入：任务与交付

| 字段 | 示例值 |
|---|---|
| evaluation_type | CLOSED_RESULT |
| user_query | 截至 2026 年 6 月 30 日，星桥 S2 正式发布后，该品牌下一场产品发布会是哪一天？发布了什么产品？ |
| query_time / temporal_scope | 2026-06-30；仅采用截至该日已公开的信息 |
| relevant_conversation | 无 |
| handoff_snapshot_id | HC-01 |
| completeness_status | 已完整恢复 |
| reference_answer | 未提供 |
| external_audit | 未执行 |
| handoff_notes | 无 |

网页清单：

| 网页 | 来源与时间 | 实际交付片段 |
|---|---|---|
| W1，快照 V1 | 星桥官方产品公告；2026-06-12 | P1：星桥 S2 已于 2026 年 6 月 12 日正式发布。 |
| W2，快照 V2 | 星桥官方活动回顾；2026-06-30 | P1：截至 2026 年 6 月 30 日，星桥品牌在本年 6 月实际举办的全部产品发布会如下：6 月 12 日发布 S2；6 月 26 日发布 T1。 |

示例地址分别为 https://example.invalid/xingqiao/s2 和 https://example.invalid/xingqiao/events-june；仅作标识，不应访问。actual_handoff_text 是以上两段文本按 W1、W2 顺序拼接；没有额外正文或隐藏附件。

#### 输出：回答义务与答案

| 义务 | 重要性 / 权重 | 状态 | 证据 |
|---|---|---|---|
| R1：确认 S2 正式发布日期 | 关键 / 3 | 充分 | W1/V1/P1：“2026 年 6 月 12 日正式发布” |
| R2：确认随后第一场发布会及其日期，排除中间另有一场 | 关键 / 3 | 充分 | W2/V2/P1：“本年 6 月实际举办的全部产品发布会”及完整日期列表 |
| R3：确认该场发布的产品 | 关键 / 3 | 充分 | W2/V2/P1：“6 月 26 日发布 T1” |

- candidate_answer：2026 年 6 月 26 日；产品为星桥 T1。
- evidence_chain：S2 于 6 月 12 日发布 → 官方完整的 6 月实际发布会记录中，下一个日期为 6 月 26 日 → 该场发布 T1。
- alternative_candidates：已审材料中无其他符合条件的候选。
- uniqueness_check：UNIQUE，依据是覆盖相关区间的完整官方活动记录，而不是简单“只搜到一个结果”。
- premise_resolution：NORMAL；关键时间锚点有交付证据。
- reference_check：NOT_PROVIDED。
- external_verification_status：未独立核验；两页属于同一机构的原始来源，不当作两份独立核验。

#### 输出：评分与阶段结论

| 维度 | 分数 | 权重 | 折算分 | 依据 |
|---|---:|---:|---:|---|
| C1 链路完整性 | 4 | 30% | 30 | 前置日期、下一场关系、产品均有支持 |
| C2 答案确定性 | 4 | 20% | 20 | 完整区间记录支持排除中间其他发布会 |
| C3 决定性事实可靠性 | 4 | 35% | 35 | 本例为低风险的机构自身历史活动，官方原始回顾直接且口径一致 |
| C4 交付可用性 | 4 | 15% | 15 | 决定性原文与时间范围完整交付，可定位 |

- assessment_status：COMPLETE。
- 结果分：100/100；表示满足本量表，不表示客观真实性有数学意义上的 100% 保证。
- 必要覆盖率：9/9＝100%。
- 核心事实支持率：9/9＝100%；本例审查发布日期、下一场关系、该场产品三项核心事实，每项权重 3，均有对应交付片段支持。
- readiness_status：READY_DIRECT；封闭结果阶段通过。
- blocker_list、review_requests：无。
- 整轨迹结论：尚未汇总，仍需 Turn 与 STOP 评估。

#### 变体：只有发布新闻，没有完整区间记录

如果 W2 只说“6 月 26 日发布 T1”，则能够确认一次后续发布，但不能确认它是“下一场”。此时必须把 R2 改为部分、uniqueness_check 改为 NOT_ESTABLISHED，并阻止 READY_DIRECT；不能保留原来的确定性满分。

## 5. 开放问题评估：具体输入与输出

### 5.1 输入内容

必填：Task、Handoff、观测完整性说明、评分政策。可选：人工范围说明、预先固定的需求骨架、独立审计材料。

不要求参考答案，不要求输入教师最终写出的答案；也不把某一篇人工参考报告视为唯一正确覆盖清单。若有参考报告，将其中合理的范围依据与外部事实分开使用。

### 5.2 特有输出

| 输出字段 | 具体内容 |
|---|---|
| answer_scope | 用户要求的范围、合理细化及仍无法确定的边界 |
| answer_obligations | 必要回答义务、来源、权重、验收条件；轻量输出即可，无固定数量要求 |
| supported_answer_outline | 各回答部分能说什么、依据在哪里，不要求完整成文 |
| claim_evidence_matrix | 核心候选事实及原文支持关系、来源可靠性、时间和限制 |
| coverage_matrix | 逐义务状态、覆盖值、引用、缺失或冲突 |
| gap_register | 内容、证据、冲突、边界四类缺口，以及对回答的影响 |
| comparison_constraints | 比较任务中的统计期间、指标、单位、对象与可比性限制 |
| prohibited_conclusions | 材料不能支撑、下游应避免作出的结论 |
| scorecard | O1 充分性、O2 事实支持与可靠性、O3 必要覆盖、O4 缺口可辨识性 |
| readiness_status | READY、PARTIAL、INSUFFICIENT、CONFLICTED、UNRESOLVED_INTENT 或 UNASSESSABLE |
| coverage_metrics | 必要覆盖率与核心事实支持率，含分子、分母、未知项及口径 |

“事实支持度高”与“信息覆盖高”必须分开输出。Judge 应能表达：已找到的事实都可引用，但仍不足以覆盖用户需要。

### 5.3 核心事实与缺口的输出边界

claim_evidence_matrix 面向 W_final 可支持的核心候选事实及真实交付断言。没有交付的历史推理断言不进入此表的最终支持率；它们归 Turn 的 T3 审查。

没有找到某厂商的信息，是覆盖矩阵与缺口表中的一项，不应由 Judge 猜出该厂商事实填入已支持表。没有审查事实时，支持率为 N/A，而不是 100%。

O4 评价原交付能否让下游识别限制。Judge 新写出的 gap_register 只是审计产物，不能用它提高原交付的 O4。

### 5.4 完整示例：已得事实有依据，但覆盖不足

本例所有实体和网页均为虚构。

#### 输入：任务与交付

| 字段 | 示例值 |
|---|---|
| evaluation_type | OPEN_RESULT |
| user_query | 比较星桥、云岚、远帆三家机器人厂商在量产和交付上的进展与主要差异，区分规划产能、订单和实际交付。时间范围为 2026 年上半年。 |
| query_time | 2026-06-30 |
| handoff_snapshot_id | HO-01 |
| completeness_status | 已完整恢复 |
| handoff_notes | 无 |
| external_audit | 未执行 |

| 网页 | 来源与时间 | 实际交付片段 |
|---|---|---|
| W1，快照 VO1 | 星桥官方运营公告；2026-06-15 | P1：生产线已投入小批量生产，规划年产能 1000 台。截至 2026 年 6 月 15 日，公司自报已向客户累计交付 120 台。 |

示例地址分别为 https://example.invalid/robot/xingqiao 和 https://example.invalid/weekly/yunlan。实际交付只包含上述两段，没有远帆网页。这里的“自报”和“预计”必须保留，不能改写成已经独立证实的能力。

#### 输出：必要回答义务与覆盖矩阵

| 义务 | 权重 | 状态 | 覆盖值 | 依据或缺口 |
|---|---:|---|---:|---|
| R1：星桥的量产、交付进展与数字口径 | 3 | 充分 | 1 | W1/VO1/P1 有小批量生产、规划产能与截至日期的交付自报 |
| R2：云岚的量产、交付进展与数字口径 | 3 | 部分 | 0.5 | W2/VO2/P1 只有意向订单和未来计划，当前生产状态仍无依据 |
| R3：远帆的量产、交付进展与数字口径 | 3 | 缺失 | 0 | 完整交付 W1—W2 没有远帆材料 |
| R4：三家厂商的主要差异与可比性 | 2 | 部分 | 0.5 | 可以区分已交付自报与意向订单，但无法完整比较三家 |
| R5：来源、期间、状态及不能比较的限制 | 2 | 部分 | 0.5 | 原文保留“自报”“预计”，但完整比较所需边界仍有缺失 |

必要覆盖率分子为 3＋1.5＋0＋1＋1＝6.5，分母为 13，结果为 **50%**。远帆没有网页不能被解释为“远帆不适用”，其义务仍留在分母中。

#### 输出：核心事实支持矩阵

| 事实 | 规范化表述 | 权重 | 支持值 | 引用及可靠性边界 |
|---|---|---:|---:|---|
| F1 | 星桥在公告中称已开始小批量生产 | 1 | 1 | W1/VO1/P1；机构自报 |
| F2 | 星桥公告中的 1000 台是规划年产能 | 1 | 1 | W1/VO1/P1：“规划年产能 1000 台” |
| F3 | 星桥自报截至 6 月 15 日累计交付 120 台 | 1 | 1 | W1/VO1/P1；不能表述为独立审计确认 |
| F4 | 行业周刊转述云岚签署 1000 台意向订单 | 1.5 | 1 | W2/VO2/P1；是转述与意向订单，不是实际产量 |
| F5 | 该报道转述云岚预计 2027 年开始交付 | 1.5 | 1 | W2/VO2/P1；未来计划，不是当前已实现状态 |

本表事实权重合计 6，充分支持的加权分子也是 6，故核心事实支持率为 **100%（5 条已审核心事实）**。这不代表用户问题已经覆盖：另有关键厂商缺失，且事实真实性仍受自报和转述范围限制。

#### 输出：可支持提纲与禁止结论

可支持的提纲：

1. 星桥已公布小批量生产和累计交付自报，分别列出时间点及数字口径。
2. 云岚材料体现意向订单和未来交付计划，不能与星桥累计交付量直接比较。
3. 远帆缺少材料，无法形成三家完整比较；说明现有比较边界。

不能支持的结论：

- 星桥已经生产了 1000 台。
- 云岚已经量产或交付了 1000 台。
- 远帆没有量产，或者远帆进展落后。
- 仅凭这两页给三家厂商排出确定的量产能力名次。

#### 输出：缺口清单

| 编号 | 缺口与严重性 | 对回答的影响 | 原交付可辨识性 | 最小补充方向 |
|---|---|---|---|---|
| G1 | 内容缺口；关键：远帆材料缺失 | 无法完整回答三家比较 | YES，用户指定了远帆而包内完全没有其材料；这不证明远帆没有相关进展 | 搜索远帆在时间范围内的量产与交付原始资料 |
| G2 | 证据缺口；关键：云岚当前生产状态不明 | 不能据订单量判断实际量产 | YES，原文只承诺未来交付且明确区分意向订单 | 查找实际生产、交付记录或正式状态说明 |
| G3 | 边界限制；重大：指标与期间不一致 | 不能以 1000 和 120 直接比较规模 | YES，W1/W2 保留各指标名称、截至时间与预计时间 | 补充相同口径材料；若不可得，保留限制 |
| G4 | 来源限制；重大：部分关键信息来自企业自报或二手转述 | 不足以作独立验证后的强结论 | YES，原文保留归因 | 优先补原始公告；确有必要时增加独立核验 |

O4 对上述可辨识性给分，但不因 Judge 写出了 G1—G4 就视为 Search Agent 已交付这张表。本例原文的归因和限定加上用户明确列出的三家对象，足以让下游识别主要限制；仍存在如何界定完整比较范围的非阻塞说明不足。

#### 输出：量化与结论

| 维度 | 分数 | 权重 | 折算分 | 解释 |
|---|---:|---:|---:|---|
| O1 证据充分性 | 2 | 30% | 15 | 已覆盖方面也缺云岚的实际状态，只能形成局部比较 |
| O2 事实支持与可靠性 | 3 | 30% | 22.5 | 限定后的核心事实有出处，但主要依赖自报与转述，不能外推强结论 |
| O3 必要信息覆盖 | 2 | 25% | 12.5 | 关键厂商和关键状态未覆盖 |
| O4 缺口可辨识性 | 3 | 15% | 11.25 | 主要限定可从实际输入识别，但比较边界尚不完整 |

- assessment_status：COMPLETE，表示评估完成，不表示搜索任务完成。
- 结果分：**61.25/100**。
- readiness_status：PARTIAL。
- 结果门槛：不通过；O1、O3 与关键回答义务不满足。
- review_requests：当前已能确认交付缺口，无须仅为确认“包里没有远帆”再调用 Judge；事实争议若影响后续结论再升级。
- 阶段建议：补搜 G1、G2，保留来源与比较限制；整轨迹路由仍需结合过程评估。

## 6. Turn 评估：输入隔离与字段设计

### 6.1 决策输入 TurnDecisionInput

| 字段 | 必填性 | 内容与边界 |
|---|---|---|
| turn_id | 必填 | 真实决策编号，不是 HTTP 重试编号 |
| actual_messages | 必填或可靠重建 | 教师本轮实际请求，包括当时系统约束、用户问题和可见历史 |
| visibility_status | 必填 | EXACT、RECONSTRUCTED 或 INCOMPLETE，并说明重建依据 |
| visible_history_index | 有历史时填写 | 对 actual_messages 中可见旧动作、query 与网页的定位索引，不额外补入已被裁剪的历史 |
| current_response_raw | 必填 | 本轮原始模型输出，作为待评估数据 |
| current_actions | 可解析时必填 | action_id、search_goal、action_reason、query_id、query_text 等原始动作内容 |
| runtime_constraints | 有则填 | 当时有效的工具、每轮 query 上限、剩余轮数/预算；必须区分教师已知约束和仅编排器知道的约束 |
| known_execution_issues | 当时可见则填 | 教师输入中已出现的超时、空结果或错误；不得附本轮尚未返回的错误 |

actual_messages 是语义边界。索引可以增加定位编号，但不能添加教师本轮看不到的事实。教师 messages 内原有指令是评估对象的一部分，不覆盖 Judge 自身的审查规则。

若要从完整日志检查“已经被上下文裁剪掉的历史重复”，应作为额外的系统级冗余诊断，不将额外历史伪装成教师当轮所知。

### 6.2 决策输出 TurnDecisionOutput

| 字段 | 具体内容 |
|---|---|
| visible_information_summary | 只根据本轮可见前缀概括已知、假设与未知，附定位 |
| targeted_gaps | 本轮实际针对的缺口及其依据；不是来自最终结果报告的事后缺口清单 |
| action_reviews | 各 action 的目标相关性、预期用途与问题 |
| query_reviews | 每条 query 的目的、约束正确性、与历史及同批次的重叠、是否需要独立验证 |
| reasoning_findings | 对公开理由中的事实和推断逐项审查；没有相关断言则不编造 |
| scorecard | T1 目标对齐、T2 过程合理性、T3 逻辑与准确性、T4 信息非冗余 |
| critical_failures | 已确认的关键错误及责任位置 |
| decision_verdict | ACCEPTABLE、SUBOPTIMAL、INVALID 或 UNASSESSABLE |
| suggested_behavior | 需要时给出补搜、核验、澄清、恢复或停止的方向，不规定唯一搜索字符串 |
| local_training_note | 可作局部目标、需修复、不适合或待复核；不是完整轨迹 PASS |

ACCEPTABLE：决策在当时信息下合理；SUBOPTIMAL：仍有价值但存在实质可改进点；INVALID：关键错误或明显不应执行；UNASSESSABLE：关键前缀不足。数值维度分与这些结论必须有一致依据。

### 6.3 收益输入 TurnOutcomeInput

| 字段 | 必填性 | 内容与边界 |
|---|---|---|
| turn_id / current_actions | 必填 | 与已完成的决策评价对应 |
| sealed_decision_id | 必填 | 已封存的事前评分版本，防止根据结果回改 |
| prior_collection_snapshot | 必填或标记不足 | 截至本轮执行前的已采集资料，用于区分真正新增与重复采集；不含未来轮次 |
| decision_visible_snapshot | 必填或标记不足 | 本轮教师实际可见的 C_t，用于区分“以前收集过”与“本轮重新可见” |
| search_call_results | 必填 | 每条已执行 query 的状态、返回网页 ID、错误、重试与结果片段 |
| new_page_snapshots | 有正常返回则填 | R_t 的真实新返回版本及原文定位 |

每条 search_call_result 至少区分 SUCCESS、EMPTY、ERROR、NOT_EXECUTED 和 UNKNOWN。部分 query 成功、部分失败时，批次状态是 PARTIAL_SUCCESS，不能丢掉成功结果或将整批收益写成零。

### 6.4 收益输出 TurnOutcomeOutput

| 字段 | 具体内容 |
|---|---|
| execution_summary | 成功、空结果、失败、未执行、未知的 query 数量与定位 |
| gain_items | 新事实、可信度提升、消歧/冲突减少、有效导航、有效排除或无可见收益，可多项 |
| gain_basis | 新返回引用与历史对照，说明何以算新、算验证或算重复 |
| collection_novelty | 对全部既有采集池是否新增 |
| visibility_gain | 对教师当时可见内容是否新增或恢复；不与 collection_novelty 混同 |
| newly_exposed_gaps | 本轮返回新暴露的缺口，不回写为教师行动前本应知道的事实 |
| remaining_gaps | 基于截至本轮结果能判断的剩余问题 |
| tool_failures | 工具失败与恢复建议，和模型错误分开 |
| outcome_assessability | 完整、部分或不可判断，说明收益判断的记录条件 |

结果内容重复但恢复了被裁剪的重要上下文，可以同时标为“采集不新增、可见性有收益”。两类收益不影响已封存的决策分。

收益输出不得评价“教师是否已经利用本轮结果”；这一点由之后真正看到该结果的决策轮负责。

### 6.5 决策子任务禁止读取的内容

- 本轮尚未返回的搜索结果 R_t。
- t 之后的动作、最终交付包 W_final、最终 Answer。
- 最终结果 Judge 的结论、分数、完整证据账本或事后生成的需求图。
- 用后续网页或外部审计材料生成的“历史摘要”。

可复用只依据 query 得到的任务骨架，但不能复用已被未来证据修改过的版本。收益评估也只能读取截至 t 的数据，不能使用未来轮次收益证明当前结果有用。

## 7. Turn 完整示例：合理搜索，部分工具失败

本例沿用第 5 节开放问题。第 2 轮开始前，教师仅看到 W1，还没有看到 W2。

### 7.1 决策输入

|---|---|---|
| Q2-1 | SUCCESS | 返回 W2/VO2/P1，内容为第 5.4 节的云岚意向订单与未来交付计划 |
| Q2-2 | ERROR | 超时；未返回可用网页；未执行额外重试 |

prior_collection_snapshot 只含 W1；sealed_decision_id 指向上述已固定的第 2 轮决策评分。没有第 3 轮或最终结果评分进入此输入。

### 7.4 执行后输出

- execution_summary：批次 PARTIAL_SUCCESS；1 条成功、1 条工具错误、0 条已确认空结果。
- gain_items：新增云岚的意向订单与预计交付计划；明确订单不能当成实际交付。
- gain_basis：W2/VO2/P1，与既有采集池 W1 的星桥信息不同。
- collection_novelty：云岚材料新增；远帆无返回。
- visibility_gain：云岚材料对下一次包含它的教师请求可形成新增信息；是否实际被放入下一轮 messages，仍以日志为准。
- remaining_gaps：云岚实际生产状态仍不明；远帆仍无资料；三家完整比较尚不能完成。
- tool_failures：Q2-2 超时，可考虑有限重试或调整检索，但不能因此推断远帆没有相关进展。
- outcome_assessability：完整可评。
- 决策评分：保持原 100 分，不因超时回改；整体交付准备度仍可能不足。

## 8. STOP 评估的具体输入输出

### 8.1 输入

复用 TurnDecisionInput 中的 actual_messages、visibility_status、当前原始响应和真实约束，但动作类型是 STOP，不附虚构的 search_queries 或本轮工具结果。

不直接使用最终结果 Judge 的 READY 标签代替 STOP 判断。即使最终交付充分，也要检查教师停止时是否已经看到了这些证据，以及停止理由是否真实。

### 8.2 输出

| 字段 | 含义 |
|---|---|
| stop_claim | 原始 STOP 的理由与完成声明，不替教师改写 |
| readiness_at_stop | 按实际可见前缀判断充分、部分、不足、冲突或不可判断 |
| unresolved_requirements | 当时仍未完成的必要目标及依据 |
| stop_reason_grounding | STOP 理由是否得到当时材料支持 |
| feasible_next_step | 当时是否仍存在有合理预期收益且符合预算的下一步；未知时不臆断 |
| stop_type | SUFFICIENT、BOUNDARY、PREMATURE、FALSE_CLOSURE 或 UNASSESSABLE |
| premature_stop_flag | YES、NO 或 UNKNOWN；与 stop_type 分开，错误闭环可能同时过早 |
| stop_score | 可评时 0—4，依据主方案锚点 |
| success_stop_eligible | YES、NO 或 REVIEW，是否可用作成功停止示范 |
| blocker_list | 关键缺口、虚假断言、冲突或观测问题 |

BOUNDARY 可以拥有高过程分，但 readiness_at_stop 仍为部分或不足，success_stop_eligible 为 NO。它可以成为边界处理样本，不是成功闭环样本。

### 8.3 示例：材料只有两家，却宣称三家已闭环

接第 7 节，假设第 3 轮实际 messages 包含 W1、W2、远帆超时记录和用户问题，教师知道最多 10 轮。

原始 STOP 理由：三家厂商的规模量产和交付都已得到确认，可以结束搜索。

输出应为：

| 输出项 | 结果 |
|---|---|
| readiness_at_stop | PARTIAL |
| stop_reason_grounding | 不成立：W2 是意向订单和未来计划；没有远帆状态资料 |
| unresolved_requirements | 云岚实际生产状态、远帆量产与交付信息、完整三家比较 |
| feasible_next_step | YES，可有限重试远帆，并继续核验云岚；当时仍有轮数 |
| stop_type | FALSE_CLOSURE |
| premature_stop_flag | YES |
| stop_score | 0/4 |
| success_stop_eligible | NO |
| blocker_list | 把计划当成已实现状态；在无远帆材料时声称已确认三家 |

如果不是教师输出 STOP，而是第 2 轮结束后被系统强制终止，则不生成以上 STOP 评价；termination_type 写实际原因，STOP 为 N/A，也不得伪造第 3 轮。

## 9. 阶段结果如何汇总

### 9.1 汇总输入

- 封闭或开放结果评估报告；混合问题则包含各子任务报告及事先固定的权重。
- 所有实际搜索轮的 TurnDecisionOutput。
- 对应 TurnOutcomeOutput，用于诊断收益，不改变事前分数。
- 实际 STOP 评价，或明确的非模型结束原因。
- 规则检查与观测缺失结果。
- 固定版本的权重、硬门槛与复核政策。

### 9.2 汇总输出

| 输出 | 含义 |
|---|---|
| result_readiness | 交付是否充分；封闭与开放按各自门槛判断 |
| result_score | 结果分 S_R；不可完整评估时不输出完整数值 |
| turn_score_summary | 每轮分、维度均分、最低轮分、关键错误轮与可评估覆盖 |
| process_score | 可评搜索轮的平均 S_P；STOP 单列 |
| stop_summary | 停止类型、分数、是否过早，以及实际终止来源 |
| optional_total_score | 仅 S_R、S_P 完整时展示 0.7 × S_R＋0.3 × S_P，不用于豁免硬门槛 |
| hard_gate_results | 每个门槛的 PASS、FAIL 或 UNKNOWN 及依据 |
| trajectory_route | PASS、REPAIR、REVIEW 或 REJECT；只有此层给整轨迹路由 |
| training_use | 完整成功候选、局部目标候选、边界/恢复候选、需修复或不使用 |
| repair_or_review_plan | 精确指出需要修复的输入、动作、交付或评估记录 |

### 9.3 各类分数不能越权解释

- CLOSED_RESULT 的 READY_DIRECT 不代表搜索过程无误。
- OPEN_RESULT 的事实支持率 100% 不代表覆盖率 100%。
- TURN_DECISION 的 100 分不代表这轮一定有实际收益。
- TURN_OUTCOME 的有益返回不证明动作事前就合理。
- STOP 的高分不代表结果充分，可能是合理边界停止。
- assessment_status＝COMPLETE 不代表 trajectory_route＝PASS。

混合问题中，关键封闭子问题未通过时，不得用开放部分的高分平均掩盖。无搜索轮、不可评估维度和系统强制结束应按 N/A/UNKNOWN 规则处理，不能补造满分。

## 10. 交付给 Judge 的组织顺序与输出约束

### 10.1 封闭/开放结果输入的顺序

1. Judge 的职责、当前题型 rubric 和输出要求。
2. 用户任务与时间、范围。
3. 已恢复的实际交付包与网页定位索引。
4. 可选参考或外部审计材料，显式标明“不属于原交付证据”。

没有实际交付的 STOP 理由、全轨迹总结与教师自评分不应混进第 3 项。若实际交付包含教师摘要，则如实保留，但摘要中的事实断言也要回溯网页，不能把自述当作独立证据。

### 10.2 Turn 输入的顺序

决策任务：Judge 职责与 rubric → 当轮实际请求 → 本轮待评估输出 → 仅影响执行可行性的已知运行约束。

收益任务：收益职责 → 截至本轮前的采集和可见性快照 → 本轮动作与返回。事前评分已封存，不附未来结果。

停止任务：STOP rubric → STOP 前实际请求 → STOP 输出 → 当时约束。

### 10.3 固定 Markdown 输出标题

| 评估单元 | 按顺序输出的报告部分 |
|---|---|
| 封闭问题 | 评估范围与可评估性；最小答案与证据链；唯一性与参考对照；量化评分；阻塞与复核；阶段结论 |
| 开放问题 | 评估范围与必要义务；可支持提纲；核心事实支持；覆盖矩阵；缺口与禁止结论；量化评分；阶段结论 |
| Turn 决策 | 当时已知与未知；逐 action/query 审查；公开理由检查；T1—T4；决策结论与局部使用建议 |
| Turn 收益 | 执行状态；收益与证据；采集新增/可见性收益；剩余缺口；工具问题 |
| STOP | 原始停止声明；停止时准备度；未闭环目标；停止类型与分数；成功停止资格 |

评分表每项必须有依据。事实判断需要原文位置；缺失判断需要已审范围；主观改进建议应标为建议而不是已证实的最优解。模型输出的是简短可审计解释，不需要暴露或构造完整隐含推理。

## 11. 输入输出验收清单

1. 每项引用都能回到本阶段允许访问的快照，而不是仅存在于全局文件池。
2. 结果阶段引用的所有支持材料都属于实际交付；外部审计材料没有增加覆盖分。
3. Turn 决策没有读取本轮返回、未来轨迹、未来修改的需求清单或最终结果报告。
4. 已确认空结果、工具失败、未执行与记录缺失没有混同。
5. 部分成功批次保留各 query 状态，不因某条超时抹掉其他收益。
6. 候选答案匹配参考答案但证据不足时，不能通过封闭准备度门槛。
7. 已支持事实集合很小时，必须同时报告缺失义务，防止支持率掩盖低覆盖。
8. 数值权重、分子分母和折算分可复算；示例中的 100、61.25、50% 与 100% 分别对应不同对象。
9. 未知分数与真正 N/A 分开；不把两者填写为 0 或 4。
10. 整轨迹路由只由汇总层给出；任何单阶段结论都不能代替完整 PASS。

本文定义的是可实施的接口语义和报告形式；未实现评估程序，也未声称这些阈值已经通过生产数据校准。
